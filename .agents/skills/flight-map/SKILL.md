# 航线地图（flightmap）

Shirley 桌面端认识一个自定义围栏语言 `flightmap`：正文里出现 ```flightmap 代码块时，
聊天内容框会渲染可展开、缩放、平移的地图。机场标签自动避让，放大后显示更多信息；
点击地点或航段可查看完整备注。底图是本地中国省界示意图，不是街道导航地图。

## 何时用

只要回答里出现「一组地点」（多个城市 / 机场 / 可达目的地 / 联程中间点 / 行程环线），
就在正文合适位置追加一个 `flightmap` 代码块。它**替代或补充**纯文字/表格列表，让用户
不必逐行读就能看清各地点的相对位置。

## 格式

代码块内容是一个 JSON 对象，**必须是合法 JSON**（用反引号包住，不要写注释）：

```flightmap
{
  "title": "北京出发随心飞可达城市",
  "origin": { "name": "北京首都", "lat": 40.08, "lon": 116.58 },
  "points": [
    { "name": "三亚", "lat": 18.25, "lon": 109.51, "label": "HU7079 08:00" },
    { "name": "成都", "lat": 30.58, "lon": 103.95 }
  ]
}
```

字段：

- `title`（可选）：地图标题。
- `origin`（可选）：起点，用强调色高亮。没有 `path` / `routes` 时，兼容旧格式，从起点连到各点。
- `points`（必填，非空数组）：要标记的地点。每项 `{name, lat, lon, label?, code?}`：
  - `name` 必填（城市/机场名）；
  - `lat` / `lon` 必填（十进制度数，北纬/东经为正）；
  - `label` 可选（地点备注；缩小时隐藏，点击可查看全文）；
  - `code` 可选（三字码，用于引用机场；放大后显示）。
- `path`（可选）：按机场 `code` 或精确 `name` 排列的行程，可以重复访问同一机场。
  地点只定义一次，例如 `["PEK", "SHA", "HGH", "PEK", "XIY"]`。
- `closed: true`（可选）：配合 `path` 自动补上最后一站到第一站；只有用户要求环线时才添加。
- `routes`（可选）：显式有向航段 `[{"from":"PEK","to":"SHA","label":"航班号/时间/状态"}]`。
  按行程顺序排列，不能和 `path` 同时提供。闭环时显式提供最后一站回到第一站的航段。
- `mode: "itinerary"`：省略 `path` 时按 `origin` + `points` 顺序串联；`mode: "loop"` 还自动闭环。
  复杂行程优先明确写 `path` / `routes`。只标地点而不连线用 `mode: "points"`。

## 行程和环线

多段行程必须给出 `path` 或 `routes`。仅给地点会被旧格式画成起点辐射图，**不能表达行程顺序**。
不要指望渲染器从标题或地点备注推断航段。

带逐段信息的环线：

```flightmap
{
  "title": "行程环线（格式示例，非可售航班）",
  "origin": { "name": "北京首都", "code": "PEK", "lat": 40.08, "lon": 116.58 },
  "points": [
    { "name": "上海虹桥", "code": "SHA", "lat": 31.20, "lon": 121.34 },
    { "name": "杭州萧山", "code": "HGH", "lat": 30.24, "lon": 120.43 }
  ],
  "routes": [
    { "from": "PEK", "to": "SHA", "label": "第 1 段，航班待核验" },
    { "from": "SHA", "to": "HGH", "label": "第 2 段，交通方式待确认" },
    { "from": "HGH", "to": "PEK", "label": "第 3 段，航班待核验" }
  ]
}
```

## 注意

- 航段备注放在 `routes[].label`，不要把所有航班号塞进地点名称。箭头表达方向，编号对应航段顺序。
- 同一机场仅定义一次；引用的 `code` / `name` 必须唯一存在。往返用两条有向航段，渲染器分弧线显示。
- 图上的连接只表示提供的行程，不能当作航班已核验或可售的证明。缺口、未核验、地面交通等写明在对应航段备注中。
- 经纬度必须真实（用机场/城市的实际坐标）；组件是示意图，不做地理纠偏，
  数据错就会标错位置。
- 一个回答里通常只放**一个** `flightmap` 块；地点很多时选关键的那些，避免图上拥挤。
- 代码块要闭合、JSON 要合法，否则渲染器会显示「数据无法解析」。
