# 多服务商与手动模型列表

模型管理同时适用于桌面和云端 Web。顶栏的设置图标，或输入框旁模型列表中的“管理模型服务商”，打开同一管理界面。设计参考 [CC Switch 的服务商编辑与获取模型流程](https://github.com/farion1231/cc-switch/blob/main/docs/user-manual/en/2-providers/2.3-edit.md)。

## 使用

1. 点击“新增服务商”，填写名称、接口协议、接口地址及 API Key。本地无认证服务可留空密钥。
2. 协议支持 Chat Completions、Responses、Anthropic Messages。地址可以是根地址、`/v1` 或对应协议的完整地址；自定义完整路径保持原样。名称需能区分不同服务商。
3. 用“手动添加”填写实际模型 ID 和显示名称，也可以“从接口获取”，勾选后批量添加。获取失败不会替换已编辑的模型列表，可继续手动填写。
4. 每个模型独立设置上下文长度、图片能力、工具调用模式、思考开关和推理强度。默认不启用图片或思考，默认上下文 65,536。能力需符合实际接口；获取模型列表成功不等于模型推理验证成功。
5. 选择服务商的默认模型；勾选“设为新聊天的默认服务商和模型”后，新聊天立即使用它，无需重启。更改整个应用默认服务商需在目标服务商中设置。
6. 保存后，从聊天的模型下拉框选择对应服务商/模型。即使选的是当前项，也会重新应用它最新的连接配置。保存编辑本身不会重配已打开的聊天或打断正在进行的请求。

高级设置支持自定义模型列表 URL 和 JSON 额外请求参数。Anthropic 兼容服务如果需要思考预算，可通过额外参数补充其要求的 thinking 配置；不支持相应能力的服务请保持关闭。

“导入原有连接”读取原有 `config.toml` 和有效环境变量，导入当前连接及默认模型，再由用户补充该服务商的模型列表。导入不改写原来的配置文件，也不会把密钥返回给浏览器或桌面前端。未配置任何服务商时，继续使用原有远端模型列表与内置回退逻辑。

## 本地与远端边界

管理界面会标注当前编辑的是“本机”还是“远端”。连接远端时，服务商设置经已鉴权的命令接口保存在远端；切回本地则编辑本机配置。开发浏览器的 mock 模式只演示界面，明确不写真实配置、不请求真实模型。

```text
~/.shirley/model-providers.json               # 服务商连接、API Key、模型与默认选择
~/.shirley/workspaces/<id>/sessions/
  <session>.model.json                        # 仅服务商/模型标识，不含密钥
```

服务商配置保存在执行端，**不参与个人记忆同步**。Unix 下配置文件权限为 `0600`。读取接口只返回“是否已保存密钥”；留空保留旧密钥，勾选“清除已保存的密钥”才清除。地址或协议变更时不复用旧密钥，防止把旧服务商的凭据发给新服务商。编辑期间若其他窗口保存了配置，会拒绝旧版本，要求重新加载。

不同服务商下同名模型使用不同选择标识。切换时一起应用协议、地址、密钥、实际模型 ID、上下文、图片能力、工具调用、思考和额外参数，不会只换模型名而残留旧连接。子任务跟随父聊天当前模型连接；未单独设置记忆整理模型时，后台记忆整理也跟随该聊天的连接。

聊天选择会单独保存，重开聊天后按绑定恢复，聊天移动和删除也处理这份绑定。服务商或模型被删除后，已有聊天要求重新选择模型，不会静默改用另一家。正在执行的请求使用开始执行时的配置直至结束。默认服务商删除后，新聊天默认改为剩余第一家；所有服务商删除后，新聊天回到原有连接配置。

## 手动验收（UI 未经用户实际验证）

未新增 UI 单元测试。以下行为需要用户实际验收：

| 改动点 | 步骤 | 预期结果 |
| --- | --- | --- |
| 管理入口 | 点击顶栏设置图标，再尝试从模型下拉框打开管理 | 都能打开模型服务商界面；能看到本机/远端范围 |
| 手动模型 | 新建服务商，添加两个模型 ID、别名及能力，保存 | 模型下拉框按服务商分组，显示配置的别名 |
| 多服务商同名模型 | 两家都填同一实际模型 ID，分别切换并发消息，检查各接口日志 | 两家各自收到对应请求，地址、密钥、协议没有串用 |
| 修改当前连接 | 编辑当前服务商的 Key 或能力并保存；再点击模型下拉框中的当前项 | 重新应用最新配置；保存本身不打断当前请求 |
| 默认模型 | 把另一家设为默认，创建新聊天，再重开原聊天 | 新聊天用新默认；原聊天保留自己的绑定 |
| 获取列表 | 填正确地址/密钥并点击获取，勾选部分模型添加；再尝试错误地址 | 仅勾选项加入草稿；失败有提示，原模型列表不丢失 |
| 密钥保留与隔离 | 重开编辑保持 Key 空白保存，再修改地址保存 | 同地址空白保留；改地址不会沿用旧 Key，需重新填写 |
| 删除 | 删除一个被聊天使用的服务商，再尝试该聊天发消息 | 提示重新选模型，聊天记录保留，不自动发给其他服务商 |
| 重启与移动 | 选模型后聊天，重启并加载；再把聊天移到另一个本机项目 | 绑定仍正确；项目内容和聊天历史正常 |
| 本地与远端 | 在本机新增服务商，再切远端打开设置 | 两端列表独立；远端配置使用已有连接令牌鉴权 |
| 小窗口与键盘 | 缩小窗口，用 Tab 操作模型表单、关闭与保存 | 内容可滚动，输入可达，Esc/关闭按钮行为正常 |

自动验证覆盖服务商 CRUD、配置并发修改、密钥脱敏与保留规则、同名模型路由、会话绑定恢复与删除处理、接口列表获取，以及子任务实际请求跟随父服务商。类型检查和构建通过不代表 UI 验收通过。
